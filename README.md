# Underside

## 公開URL

ブラウザ上でプレイできます。  
URL：https://unityroom.com/games/underdside

## 概要

「Underside」は、どちらのスライムが勝利するかを予想する賭けゲームです。

プレイヤーは計3回の賭けフェーズでスライムの勝敗を予想し、最終的なコインの所持数によってエンディングが分岐します。

## 制作背景

前作ではGit管理や進捗の整理に課題があったため、本作では作業の区切りごとにブランチを分け、進捗を後から確認しやすい形にすることを意識しました。

また、ゲームの流れを状態ごとに分けて管理することや、UniTaskを使った演出処理に挑戦することを目的として制作しました。

## 使用技術

- Unity
- C#
- UniTask

## 実装した主な機能

- スライム同士の自動バトル
- 勝敗予想システム
- 賭け金システム
- コイン数によるエンディング分岐
- UniTaskを活用したアニメーション処理
- ゲーム進行のステート管理

## 工夫した点

### ステート管理によるゲーム進行

ゲームの流れを、賭けフェーズ、バトルフェーズ、結果表示、エンディング分岐のように状態ごとに分けて管理しました。

処理を状態ごとに分けることで、現在どの処理を行っているのかを整理しやすくし、ゲーム全体の流れを把握しやすくすることを意識しました。

### UniTaskを使った演出処理

バトル中のアニメーションや結果表示のタイミング調整にUniTaskを活用しました。

処理を一気に進めるのではなく、演出に待機時間を入れることで、プレイヤーが状況を理解しやすくなるように工夫しました。

### UIの見やすさ

プレイヤーが現在のコイン数や賭けの状況を理解しやすいように、UIの見やすさを意識しました。

賭けゲームでは、プレイヤーが「今どちらに賭けているのか」「結果として何が起きたのか」をすぐに理解できることが重要だと考え、情報の見せ方を工夫しました。

## 生成AIの活用について

本作では、生成AIを以下の用途で活用しました。

- ステート管理の考え方の整理
- UniTaskを使った処理の書き方の確認
- 賭け金システムの実装方針の相談
- エラー原因の切り分け
- コード改善案の比較

ただし、生成AIの出力をそのまま使うのではなく、ゲームの仕様に合っているかを確認しながら実装しました。

特に、賭け金システムやゲーム進行の処理では、実際にUnity上で動作確認を行い、意図した流れになるように修正しました。

## 反省点

制作してみて、もっと単純な設計にすればよかったと感じました。

特にオッズ機能は、自分が入れてみたかった機能でしたが、本作は1対1の勝敗予想であるため、ゲーム性に大きな意味を持たせることができませんでした。

この経験から、ゲーム制作では「入れたい機能」を増やすだけでなく、「その機能がゲームの面白さにつながっているか」を考えることが重要だと学びました。

今後は、機能を追加する前に、以下の点をより意識したいです。

- プレイヤーにとって分かりやすいか
- ゲーム性を高める機能になっているか
- 実装後も管理しやすい設計になっているか

## 学んだこと

この作品を通して、ゲームの進行管理や演出処理だけでなく、機能の取捨選択の重要性を学びました。

また、生成AIを活用することで実装方針の整理やエラー解決を効率化できる一方で、最終的には自分で仕様を判断し、必要な機能かどうかを見極めることが大切だと感じました。

## 今後の改善点

今後は単純な設計で作成して、ユーザーにもわかりやすいようなゲームをしていきたいと思いました。

今回は生成AIを過信しすぎてしまった部分があり、複雑な設計をしてしまい管理が追い付かなかったです。
今後は単純な設計でより多くのコンテンツが遊べるようなゲームで作成していきたいです。
